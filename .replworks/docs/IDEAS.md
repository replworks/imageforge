# IDEAS.md — ImageForge (이미지 리사이징 + CDN 서비스)

> 목적: "이걸 실행할 것인가, 말 것인가"를 사람이 판단하기 위한 문서.
> 정밀성은 PRODUCT_SPEC / ARCHITECTURE 단계에서 확보한다. 여기서는 판단 근거만 적는다.
> 표기: **[출처]** 사용자 진술·확인된 사실 / **[추론]** 논리적 추정 / **[의견]** 판단

---

## 1. 한 줄 요약

원본 이미지를 URL 파라미터로 리사이징·포맷 변환하고 Cloudflare 엣지에서 캐시해 제공하는, **한국 사업자 대상 유료 이미지 CDN 서비스**.

## 2. 해결하려는 문제

- **[출처]** 자체 이커머스 운영 경험(5년)과 여러 서비스 개발에서 이미지 리사이징/전송이 반복되는 pain point였다.
- **[추론]** 해외 서비스(Cloudinary, imgix 등)는 한국어 지원, 원화 결제, 세금계산서/PG 영수증, 국내 SLA 측면에서 소규모 한국 사업자에게 마찰이 있을 수 있다. (검증 필요)

## 3. 차별화

- **[출처]** 확정된 프레이밍: 유료 한국 서비스의 가치 = **책임 소재, SLA, PG 영수증**.
- **[의견]** 기술(리사이징)은 imageproxy 오픈소스로 동일하므로 기술 차별화는 없다. 차별화는 전부 운영·계약·결제 영역에 있다. 이 가정이 틀리면 사업이 성립하지 않는다.

## 4. 구현 접근

| 항목           | 결정                                            | 근거                                                 |
| -------------- | ----------------------------------------------- | ---------------------------------------------------- |
| 엔진           | imageproxy                                      | Buy before Build. 직접 만들 이유 없음                |
| DNS/프록시     | Cloudflare (hosting.kr에서 이전 완료)           | 프록시는 Cloudflare가 권한 네임서버여야 동작         |
| 캐시 무효화    | **purge 방식** (URL 버전 미사용)                | 이미지 URL을 고객 코드에 박지 않게 하려는 선택       |
| 캐시 TTL       | 브라우저 짧게 / 엣지 길게 분리                  | purge는 엣지만 비우므로 브라우저 TTL이 길면 무력화됨 |
| 변형 구분      | query string (`w`, `h`, `q`, `f` 등)            | prefix purge 한 번으로 모든 변형 무효화 가능         |
| 포맷 협상      | Accept 헤더 대신 `f=` 파라미터 (Free 플랜 기준) | Vary for Images는 Pro 이상                           |
| 랜딩           | `cdn.repl.net`                                  |                                                      |
| Operator purge | `cdn.repl.net/purge`, Cloudflare Access 뒤      | DB 없이 로그인 해결                                  |
| Rate limiting  | 현재 미설정 (단독 사용 단계)                    | **공개 전 재검토 필수**                              |

## 5. 고객 확보 (수익보다 우선)

- **[미확인]** 첫 고객 후보, 확보 경로, 가격 가설은 아직 논의되지 않았다.
- **[의견]** 이 항목이 비어 있는 한 "실행" 판정은 보류가 맞다. 가장 먼저 채울 칸이다.

## 6. 주요 리스크

1. **임의 크기 요청 남용** — 캐시 미스마다 원본 CPU를 쓴다. 공개 전 signature key 또는 허용 크기 목록 필요. (현재 rate limiting 없음)
2. **Cloudflare 종속** — DNS, 프록시, 인증(Access), 캐시가 모두 한 벤더에 걸려 있다.
3. **원본 서버 직접 접근** — Access/프록시는 Cloudflare를 거친 요청만 보호한다. 서버 IP 직접 호출 차단(방화벽 또는 JWT 검증) 필요. 공유 호스팅이면 JWT 검증으로 대응.
4. **purge 운영 부담** — 갱신 로직과 purge 호출이 분리되면 "옛날 이미지가 계속 나오는" 장애를 추적하기 어렵다.
5. **가격 경쟁** — 기술 차별화가 없으므로 해외 서비스의 무료/저가 플랜과 직접 비교된다.

## 7. 반증 조건 (이 중 하나가 참이면 중단)

- 유료 의사가 있는 한국 사업자를 N곳 확보하지 못한다. (N과 기한은 사람이 정한다)
- 고객이 SLA/PG 영수증에 추가 비용을 지불할 이유가 없다고 답한다.
- 운영 비용(서버 + Cloudflare 플랜 + 대응 시간)이 월 매출을 지속적으로 초과한다.
- imageproxy 외 대안(Cloudflare Images 등)이 같은 가격대에서 동일한 한국 지원을 제공한다.

## 8. 완결성 판정

- 기술 실현 가능성: **충분** (엔진, 캐시, 인증 구조가 정해짐)
- 시장/고객 검증: **미흡** (고객, 가격, 확보 경로 미정)
- **판정: 조건부 보류.** 5번 항목(첫 고객 후보 3곳 이상, 가격 가설)을 채운 뒤 go/no-go를 결정한다.
